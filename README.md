## 웹 · 휴대폰 앱 (PWA)

동일한 홈페이지를 브라우저 또는 홈 화면에 설치한 앱으로 이용할 수 있습니다.
- 안드로이드: Chrome 메뉴 → 앱 설치 / 홈 화면에 추가
- 아이폰·아이패드: Safari 공유 → 홈 화면에 추가 → 추가 (웹 앱으로 열기가 표시되면 켬)
- PC: Chrome·Edge 주소창 설치 아이콘 또는 브라우저 메뉴에서 앱 설치
- 첫 온라인 방문 시 회사소개와 주요 사진을 저장합니다. 이후 오프라인에서도 해당 콘텐츠를 볼 수 있습니다. 외부 사이트·문의 기능은 별도 연결이 필요합니다.

앱 파일: manifest.webmanifest, sw.js, app.js, app.css, assets/app-icon-192.png, assets/app-icon-512.png, assets/apple-touch-icon.png.
앱 설치는 HTTPS 또는 localhost에서 사용합니다. 앱스토어·플레이스토어 패키지가 아니라 홈 화면에 설치하는 웹 앱입니다.
수정 배포 시 sw.js의 CACHE_NAME 버전을 변경하세요. 앱에 새 버전 안내가 표시되면 사용자가 선택하여 갱신합니다. 모바일 실기기 설치 확인은 기기에서 진행해야 합니다.

설치 안내 기준: [MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable), [Apple](https://support.apple.com/guide/iphone/iphea86e5236/ios).

## 비윤리 신고 안내

[비윤리 신고 페이지](./ethics.html)를 홈페이지 상단 메뉴와 하단 안내, 앱 바로가기에 연결했습니다.
신고·보상 안내 / 신고하기 / 처리결과 확인 탭을 PC·모바일에서 이용할 수 있습니다.
전용 신고 접수처와 보상 정책은 제공되지 않아 확정된 회사 제도로 게시하지 않았습니다. 대표메일로 신고 및 처리상황 문의 메일을 작성할 수 있으며, 메일 앱에서 직접 전송해야 합니다. 작성 양식 다운로드만으로 접수되지는 않습니다.
신고 수집, 익명 접수, 접수번호 발급 및 온라인 결과조회 서버는 연결하지 않았습니다. 처리결과는 접수 담당자에게 문의하도록 안내합니다.
운영 시 회사가 확정한 전용 접수처, 정보 취급·보호 기준, 보상제도 및 처리 절차를 반영하세요. 비윤리 신고 안내와 양식은 앱 오프라인 캐시에 포함됩니다.

비윤리 신고 추가 기능: 신고 작성 및 처리상황 문의 양식을 입력하면 대표메일 highnoon0377@naver.com으로 보낼 메일을 준비합니다. 사용자가 메일 앱에서 직접 전송해야 합니다. 본문 복사·텍스트 저장을 지원하며 입력 내용을 서버/브라우저 저장소에 저장하지 않습니다. 긴 내용은 제목만 메일로 넘기고 본문 복사를 안내합니다. 자동 접수와 온라인 결과조회는 제공하지 않습니다.

첫 접속 시 메인 이미지 위에 비윤리 신고·처리상황 문의 안내와 두 개의 바로가기 버튼을 표시합니다. PC·모바일에서 로그인이나 추가 메뉴 클릭 없이 안내를 확인할 수 있습니다.

## 현장 작업자 장애발생 보고서 (2026-10-24)

[장애발생 보고서](./incident.html): 현장·설비 정보, 장애 증상·영향, 원인·조치·후속 조치, 사진 최대 4장을 기록합니다. 복구완료 시 복구일시를 입력하며 발생~복구 시간을 계산합니다.
기기 임시저장 버튼으로 현재 브라우저의 IndexedDB에 보고서 1건과 사진을 보관합니다. 자동 저장·서버 접수·기기간 동기화는 없습니다. 불러오기와 기기 임시저장 삭제를 제공합니다.
미리보기 후 사진을 포함한 독립 HTML 보고서를 내려받거나 인쇄 창에서 PDF로 저장합니다. 파일은 회사가 지정한 방법으로 별도 전달해야 합니다. 원본 사진은 10MB 이하, JPG/PNG/WebP만 지원하며 보고서용 1600px 이하 JPEG로 줄여 첨부합니다. 사진의 원본 보존 용도로 사용하지 않습니다.
홈페이지 첫 화면, 상단·하단 메뉴, 앱 바로가기에 연결했으며 오프라인 앱 캐시에 포함합니다.

## 중요공사기간관리 (2026-11-19)

[관리 화면](./construction.html)을 홈페이지 본문 맨 위(장애보고서 위), 하단 메뉴, 모바일 빠른 메뉴와 앱 바로가기에 연결했습니다.
- 공사명, 초고속·전용·무선·기타 구분, 시작일·마감일, 담당자, 발주처·현장, 메모 등록·수정·삭제
- 작업지시 / 연기(임시) / 진행 / 완료 보드 및 전체 목록, 검색·구분·기간 표시 필터
- 한국 날짜 기준 2일 전 주황, 1일 전·마감 당일 빨강, 기한 경과 파랑, 기간 내 완료 초록. 완료일이 마감일보다 늦으면 지연 완료(파랑)
- 공사별 실제 완료일 기록, 완료 여부·지연일 표시, JSON 백업·불러오기 및 목록 인쇄

이번 단계는 브라우저 로컬 저장(localStorage, 최대 500건)입니다. 공용 DB 동기화·계정 인증·문자/푸시 알림은 연결하지 않았습니다. 실제 공사 데이터를 예시로 미리 채우지 않습니다. 회사 공사 데이터는 GitHub에 업로드되지 않으며 백업 파일에는 입력 내용이 포함됩니다.
construction-core.js는 날짜·표시 판정, construction-store.js는 list/upsert/remove/replace 저장소 경계, construction.js는 화면 동작을 담당합니다. 추후 Netlify·Supabase 연동 시 저장소 경계를 교체하고 사내 사용자 인증과 행별 접근 정책을 먼저 적용해야 합니다. 이 버전에는 원격 DB 주소·키·마이그레이션을 포함하지 않습니다.
기존 GitHub Pages는 계속 사용 가능하며 새 관리 화면과 관련 파일은 앱 오프라인 캐시에 포함됩니다. Netlify로 주소가 바뀌면 브라우저 저장 데이터가 자동 이전되지 않으므로 백업 후 불러오기를 사용하세요.


### 중요공사기간관리 1차 보완

등록창의 공사명을 공사번호로 변경하고 담당자·발주처 입력란을 작업장 주소(한 줄 전체 폭)로 교체했습니다. 공사번호와 주소를 진행 보드·목록·검색·인쇄·백업에 반영합니다.
기존 로컬 저장 및 schema 1 백업을 계속 읽습니다. 호환성을 위해 기존 name 키를 공사번호 입력에 사용하며, 이전에 저장한 값은 자동 삭제하거나 바꾸지 않습니다. address 키를 추가하고, 기존 assignee/client 값은 화면에서 입력받지 않지만 수정·백업 시 보존합니다.

### 2차 보완: 마감 1일 전 홈페이지 접속 팝업

홈페이지 접속 시 한국 날짜 기준으로 마감일이 다음 날인 미완료 공사(작업지시·연기·진행)를 팝업으로 표시합니다. 완료 공사, 마감 당일·2일 전·지연 공사는 이 팝업 대상에서 제외합니다.
공사번호·주소·공사기간·상태와 건수를 표시하며 테두리와 알림 점에 2.4초 주기의 부드러운 깜빡임 효과를 적용했습니다. 팝업 내용과 글자는 계속 표시됩니다. 기기의 동작 줄이기 설정에서는 효과를 끕니다.
닫기·Escape·공사관리 이동을 지원합니다. 현재 접속에서 닫으면 계속 반복해서 열지 않으며, 새로고침이나 다시 접속하면 해당 공사가 있는 경우 다시 표시합니다. 기기 로컬 저장을 기준으로 하며 푸시·문자 발송 기능이 아닙니다.

### 마감 알림 확인 보완

기존 ‘마감 임박’ 요약은 0~2일 전체 합계이며 팝업은 정확히 D-1만 대상입니다. 혼동 방지를 위해 홈페이지에 하루 전·당일·2일 전 건수와 한국 기준일을 각각 표시하고, ‘마감 알림 확인’ 버튼으로 닫은 팝업을 다시 열 수 있게 했습니다. 대상이 없거나 읽기/표시 오류가 있는 경우에도 원인을 화면에 안내합니다.
알림·공사관리 스크립트와 CSS에 릴리스 버전을 붙이고 앱의 해당 파일 캐시를 온라인 우선/오프라인 캐시 방식으로 변경했습니다. 브라우저의 공사 데이터는 지우지 않습니다.



## 정식 홈페이지 및 공사 기본 자료

시연 링크·시연 모드·예시 생성 및 시연 전용 저장소 사용 코드를 제거했습니다. 기존 demo.html 주소는 홈페이지로 이동만 합니다.
사용자가 홈페이지 반영을 요청한 2026-11-19 백업의 공사 8건을 construction-initial.js에 기본 일정으로 반영했습니다. 공개하는 필드는 공사번호, 구분, 기간, 진행 상태, 완료일, 작업장 주소이며, 담당자·발주처·내부 메모는 기본 자료에서 제외했습니다. 기존 브라우저 저장 자료에는 손대지 않습니다.
새 브라우저 또는 이전 버전의 빈 목록은 기본 8건을 한 번 불러옵니다. 이후 등록·수정·삭제한 데이터는 해당 브라우저에 유지되며, 모든 공사를 삭제해도 다시 8건으로 되돌아가지 않습니다. 백업 불러오기 역시 저장한 목록을 기준으로 유지합니다.
11월 19일 기준으로 마감 1일 전 3건, 당일 3건, 기한 경과 1건, 완료 1건입니다. 마감일은 실제 제공 날짜를 유지하며 날짜가 바뀌면 팝업 대상도 달라집니다. 일정은 브라우저별 저장이며 공유 DB 자동 동기화는 아직 연결되지 않았습니다.
